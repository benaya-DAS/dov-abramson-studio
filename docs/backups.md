## מה נכלל בגיבוי

כל הטבלאות והנתונים של האפליקציה: סביבות, בורדים, קבוצות, משימות, דיווחי שעות, היסטוריית פעולות, משתמשים (profiles), קטלוג, רשימת התוצרים ודומיינים מורשים.

**לא נכלל:**
- תמונות פרופיל (נשמרות ב־Storage, לא במסד הנתונים). משתמש שהתמונה שלו תאבד יכול פשוט להעלות אותה מחדש.
- חשבונות ההתחברות עצמם (`auth.users`). אותם מנהל Supabase, והם נוצרים מחדש בהתחברות עם גוגל.

## הגדרה ראשונית (פעם אחת - כבר בוצעה)

צריך שני סודות ב־GitHub: **Settings → Secrets and variables → Actions → New repository secret**.

### `SUPABASE_DB_URL` - כתובת החיבור למסד הנתונים

1. ב־Supabase: **Connect** בראש הדשבורד ← לשונית **Direct** ← **Session pooler** (לא Direct connection, שלא עובד מ־GitHub). מעתיקים את הכתובת:
   `postgresql://postgres.fyiostdopgrivjgmzhxw:[YOUR-PASSWORD]@aws-0-....pooler.supabase.com:5432/postgres`
2. מחליפים את `[YOUR-PASSWORD]` (כולל הסוגריים) בסיסמת מסד הנתונים. סימנים מיוחדים בסיסמה כותבים בקוד: `^`→`%5E`, `(`→`%28`, `)`→`%29`, `@`→`%40`, `#`→`%23`, `/`→`%2F`, `?`→`%3F`, `%`→`%25`, `&`→`%26`, `:`→`%3A`.
3. סיסמה לא ידועה? מאפסים אותה בהגדרות מסד הנתונים ב־Supabase (Database → Settings → Database password). האפליקציה עצמה לא משתמשת בסיסמה הזו, כך שהאיפוס לא ישבור אותה.

### `GDRIVE_TOKEN` - גישה לדרייב של חשבון הגיבוי

המערכת יכולה לראות ולשנות רק קבצים שהיא עצמה יצרה בדרייב, לא שום דבר אחר.

1. **Mac:** פותחים Terminal (⌘ + רווח, `Terminal`) ומדביקים:
   ```
   cd ~/Downloads && A=$(uname -m | sed 's/x86_64/amd64/') && curl -sSLO https://downloads.rclone.org/rclone-current-osx-$A.zip && unzip -oq rclone-current-osx-$A.zip && cd rclone-v*-osx-$A && ./rclone version
   ```
   (**Windows:** מורידים את rclone מ־[rclone.org/downloads](https://rclone.org/downloads/), פותחים את ה־zip, ובשורת הכתובת של התיקייה כותבים `cmd`.)
2. באותו חלון:
   ```
   ./rclone authorize "drive" "eyJzY29wZSI6ICAiZHJpdmUuZmlsZSJ9"
   ```
   (ב־Windows בלי `./`.)
3. בדפדפן שנפתח מתחברים **עם חשבון הגיבוי** ולוחצים **Allow**.
4. בחלון מופיעה מחרוזת ארוכה בין `Paste the following into your remote machine --->` לבין `<---End paste`. מעתיקים **רק אותה** לסוד `GDRIVE_TOKEN`. **לא לשתף אותה** - זה המפתח לדרייב.
5. אפשר למחוק את rclone מתיקיית ההורדות.

אם הגיבוי מתחיל להיכשל עם שגיאת הרשאה (למשל אחרי שינוי סיסמה בחשבון הגיבוי) - חוזרים על שלבים 1-4 ומעדכנים את הסוד.

### בדיקה

**Actions → DB backup → Run workflow**. אחרי דקה־שתיים אמורים להופיע בתיקייה `db-backups` קובץ `.dump` וקובץ `.xlsx`.

## שחזור

> **שחזור מחליף את כל הנתונים הנוכחיים** בנתונים מהגיבוי. כל מה שנוסף או שונה אחרי שעת הגיבוי יאבד.
> לפני השחזור נשמר אוטומטית עותק של המצב הנוכחי בתיקייה `db-backups/pre-restore`, כך שאפשר לבטל שחזור שנעשה בטעות.

**לא צריך להוריד או להעלות שום קובץ** - השחזור לוקח את הגיבוי ישירות מהדרייב.

1. ב־GitHub: לשונית **Actions** ← **DB restore** ברשימה בצד ← **Run workflow** (מימין למעלה).
2. **backup_file**: משאירים **ריק** כדי לשחזר מהגיבוי האחרון. כדי לשחזר מגיבוי מוקדם יותר - מעתיקים מהדרייב את שם קובץ ה־**`.dump`** הרצוי (למשל `studio-backup_2026-10-05_0623.dump`).
3. **confirm**: מקלידים `RESTORE` (באנגלית, באותיות גדולות).
4. **Run workflow**. אחרי כ־2 דקות מרעננים את האפליקציה.

השחזור רץ כפעולה אחת: אם משהו נכשל באמצע, שום דבר לא משתנה במסד הנתונים.

**שחזור חלקי** (למשל רק בורד אחד שנמחק, בלי לאבד את מה שנעשה מאז בשאר הבורדים) - לא נתמך בכפתור. אפשר לפתוח את קובץ האקסל של הגיבוי ולהעתיק משם ידנית, או לבקש מ־Claude לעשות שחזור חלקי.

**ביטול שחזור:** מריצים שוב את **DB restore**, ובשדה `backup_file` כותבים `pre-restore/` ואחריו שם הקובץ מהתיקייה `pre-restore` (למשל `pre-restore/pre-restore_2026-10-05_1412.dump`).

### מצב קיצון: הפרויקט ב־Supabase נמחק לגמרי

1. יוצרים פרויקט Supabase חדש ומריצים בו את `supabase/schema.sql` (ומגדירים את Google OAuth לפי ה־README).
2. מעדכנים את הסוד `SUPABASE_DB_URL` לכתובת של הפרויקט החדש.
3. מריצים **DB restore** כרגיל.
